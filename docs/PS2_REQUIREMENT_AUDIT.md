## 3. Root-Cause Bugs Identified & Fixed in This Verification Cycle

1. **Google Fit Sleep & Missing Data Import Failures (`apps/web/src/lib/ingestion/adapters/providers.ts`, `connectors/google-cloud-health.ts`, `connectors/google-callback-handler.ts`, `api/v1/sync/provider/route.ts`, `components/ingest/watch-sync-hub.tsx`):**
   - *Bug 1A (Inverted Google Fit sleep stage enum):* `providers.ts` line 329 excluded `stageCode !== 2 && stageCode !== 3`, treating `1` (Awake in Google Fit `com.google.sleep.segment`) as sleep and `2` (Generic Sleep) as awake! Fixed to exclude `0`, `1` (Awake), and `3` (Out-of-bed) per official Google Fit REST specification.
   - *Bug 1B (Missing Sleep Sessions `activityType=72`):* Health Connect, Fitbit, Samsung, and Noise bridges commonly write sleep sessions without granular `com.google.sleep.segment` buckets. Added parallel fetch of `/fitness/v1/users/me/sessions?...&activityType=72` after granular segment fallback.
   - *Bug 1C (HTTP 400 `No default datasource found` / Missing DataSources Fallback):* When Google Fit has wearable streams under app-specific `dataSourceId`s but no default merged datasource, added automatic lookup of `/users/me/dataSources`, aggregate query by `dataSourceId`, and direct `/datasets/{startNanos}-{endNanos}` range read before giving up.
   - *Bug 1D (Expired Token False "Connected" UI & Short Lookback):* `getGoogleConnectorsStatus` now surfaces `needsReconnect: true` when tokens are expired with no `refreshToken`; `/ingest` UI renders a clear `Reconnect Required` badge + re-authorize action; default Google Fit backfill widened from `48h` to `336h` (14 days).
2. **Resting Heart Rate Series Blind Spot for Google Fit & Web BLE (`apps/web/src/lib/dashboard/queries.ts` & `apps/web/src/lib/engine/ts-fallback.ts`):**
   - *Bug 2:* `GoogleFitAdapter` and Web Bluetooth GATT (`0x2A37`) ingest canonical `heart_rate`, whereas `/today`, `/caregiver`, and `/clinician` request `metric=resting_heart_rate`. Fixed `loadVitalsSeries` to fall back to calm `heart_rate` (`sleep`, `rest`, `unknown` contexts) when `resting_heart_rate` rollups are empty, and added hourly calm `heart_rate -> resting_heart_rate` backfill in `ts-fallback.ts`.
3. **Simplified Vercel Serverless Engine Fallback (`apps/web/src/lib/engine/ts-fallback.ts`, `client.ts`):**
   - *Bug 3:* Previously `fallbackEvaluateLocal` only computed median RHR & drop from 97% SpO2, ignoring `steps`, `sleep_duration_min`, `sleep_efficiency`, `excludedPeriods` quarantine, `warming_prior/learning/calibrated` shrinkage, EWMA/CUSUM/change-points, L3 multivariate scoring, and real Partial NEWS2 parameters. Replaced with full-parity `evaluateLocalDeterministicEngine`.
4. **First-Detection Timeline Derivation & Alert Context (`apps/web/src/lib/dashboard/queries.ts`, `detection-timeline-card.tsx`, `outbox.ts`):**
   - Added DB-backed `detectionTimeline` reconstructing exact timestamps of first qualifying detection, active layers, alert confirmation, and recovery, mounted on `/clinician`, `/caregiver`, `/signals`; enriched alert copy with lead driver observed value vs personal normal range, active detection layers, first-shift timestamp, and explicit non-diagnostic guidance.
