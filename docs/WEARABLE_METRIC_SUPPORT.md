# Sachet · SENTINEL — Wearable Metric Support Matrix (PS2 Verification)

Verification rule enforced in this audit: a metric is marked **YES (End-to-End)** only when code inspection + executed tests confirm every stage from **Ingestion -> Unit Normalization / QC -> PostgreSQL Storage -> 14-Day Personal Baseline -> L1/L2/L3 Anomaly Detection -> Frontend Dashboard Chart/Card**.

## 2. Auxiliary Telemetry & Explicit Hardware / Schema Limitations

- **Supported Auxiliary Metrics:** `hrv_rmssd` (ms — computed from Web BLE `0x2A37` RR intervals, Health Connect, Watch webhook, CSV), `respiratory_rate` (breaths/min), `skin_temp_deviation` (degC), `body_temperature` (degC / degF auto-converted), `systolic_bp` (mmHg), `blood_glucose` (mg/dL & mmol/L converted), `weight_kg`, `afib_burden` (%).
- **Explicit Device / Connector Limitations:**
  1. **Web Bluetooth (`0x180D`):** Standard Heart Rate Service transmits beat-to-beat HR & RR intervals (`hrv_rmssd`) only; it **cannot** transmit Steps, Sleep, or SpO2.
  2. **Google Fit Cloud Import Caveats:**
     - Google deprecated the Google Fit Android SDK/REST API on June 30, 2025 / 2026 transition timeline in favor of Android **Health Connect**; existing accounts only return data if a watch/companion still syncs into Google Fit cloud AND grants restricted Fitness scopes (`fitness.heart_rate.read`, `fitness.activity.read`, `fitness.sleep.read`, `fitness.oxygen_saturation.read`).
     - Google Fit OAuth tokens lacking a `refresh_token` expire after ~1h (`WatchSyncHub` now detects `needsReconnect` and prompts `Re-authorize` with `prompt=consent`).
  3. **Partial NEWS2 Integrity:** Consciousness (`ACVPU`), supplemental `O2` status, and continuous passive `systolic_bp` cannot be measured by consumer wrist wearables and remain explicitly marked `unavailable_from_wearable` (never assumed 0 points).
